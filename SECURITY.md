# Security policy

## Report potential vulnerabilities privately

Do not create a public Issue for a suspected vulnerability. While this repository is private and during the publication transition, send the report to [SofiaFlux@outlook.com](mailto:SofiaFlux@outlook.com).

Include the affected revision, reproduction steps, expected impact, and a safe proof of concept. Do not send credentials, bearer tokens, private keys, raw local databases, or unredacted personal data.

## What happens after a report

We aim to acknowledge the report, triage it, develop and validate a remediation, and coordinate publication with the reporter when appropriate. These phases describe the process, not a service-level agreement or response-time commitment.

## Disclosure transition

GitHub Private Vulnerability Reporting becomes the primary reporting path only after the repository is public and that path has been verified. Until then, and afterward as a fallback, use [SofiaFlux@outlook.com](mailto:SofiaFlux@outlook.com).

This project is experimental and local-first; reports should describe the affected local configuration and enforcement level where relevant.
